# Full list of table errors detected

This document describes the validation errors currently detected by
`ckanext-validate` when validating CSV resources.

The extension uses Frictionless to infer the table structure and validate the
file. It also applies additional detection rules for numeric and date columns.

## Current validation rules

Before validating a CSV file, the extension applies the following rules:

- Every column is required.
- The values `null`, `NULL`, and `None` are treated as missing values.
- A column is considered numeric when at least 50% of its non-missing values
  can be parsed as numbers.
- A numeric column is inferred as `integer` when all detected numeric values
  are whole numbers. Otherwise, it is inferred as `number`.
- A column is considered a date column when at least 50% of its non-missing
  values use the same supported date format.
- The supported date formats are:
  - `MM/DD/YYYY`, for example `04/25/2024`.
  - `DD/MM/YYYY`, for example `25/04/2024`.
  - `YYYY-MM-DD`, for example `2024-04-25`.

After the schema is inferred, Frictionless validates every row against it.
Values that do not match the inferred type or format are reported as errors.

## Errors detected

### Header missing

**Error type:** `blank-header`

This error occurs when the CSV header row is empty. The first row must contain
the column names.

```csv
,
1,2
3,4
```

### Column name missing

**Error type:** `blank-label`

This error occurs when one or more columns in the header have no name. Every
column must have a non-empty name.

```csv
column_1,
1,2
3,4
```

### Duplicate column name

**Error type:** `duplicate-label`

This error occurs when two or more columns have the same name. Every column
name must be unique.

```csv
column_1,column_1
1,2
3,4
```

### Empty row

**Error type:** `blank-row`

This error occurs when a completely empty row is present in the CSV data.

```csv
column_1,column_2
1,2

3,4
```

### Missing value

**Error type:** `missing-cell`

This error occurs when a row has fewer cells than the header row.

```csv
column_1,column_2
1,2
3
```

### Extra cell

**Error type:** `extra-cell`

This error occurs when a row has more cells than the header row. Every data row
must have the same number of cells as the header.

```csv
column_1,column_2
1,2
3,4,5
```

### Type mismatch

**Error type:** `type-error`

This error occurs when a value does not match the data type inferred for its
column.

For example, when most values in a column are numeric, a text value is
reported as invalid:

```csv
amount
100
250.50
300
invalid
```

The same rule applies to date columns. Once a date format is inferred, values
using another format or containing invalid dates are reported as errors:

```csv
date
2024-04-25
2024-05-10
25/06/2024
```

### Required value missing

**Error type:** `constraint-error`

Every inferred field is configured as required. This error occurs when a
required cell contains a missing value.

The values `null`, `NULL`, and `None` are explicitly treated as missing:

```csv
column_1,column_2
1,2
3,null
4,None
```

### Structural validation error

**Error type:** `structure-error`

This is a fallback error generated by `ckanext-validate` when Frictionless
marks the resource as invalid but does not provide row-level error details.

It indicates that the file contains a structural problem that could not be
represented as one of the detailed errors listed above.

## Error report behavior

Validation errors are grouped by error type in the report.

For every group, the report displays:

- The error title and description.
- The total number of occurrences.
- A preview of the affected rows and cells.
- Up to 20 affected rows.

When an error group contains more than 20 rows, the report indicates that only
the first 20 are being displayed.
