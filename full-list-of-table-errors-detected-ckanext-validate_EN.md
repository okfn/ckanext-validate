# Full list of table errors detected

This document describes the validation errors currently presented by
`ckanext-validate` when validating CSV resources.

The extension uses Frictionless to infer the table structure and validate the
file. It also applies additional detection rules for numeric and date columns.

## Validation rules

Before validating a CSV file, the extension applies the following rules:

- Every inferred column is configured as required.
- The values `null`, `NULL`, and `None` are treated as missing values.
- A column is considered numeric when at least 50% of its non-missing values
  can be parsed as numbers.
- A numeric column is inferred as `integer` when all detected numeric values
  are whole numbers. Otherwise, it is inferred as `number`.
- A column is considered a date column when at least 50% of its non-missing
  values use the same supported date format.
- The supported date formats are:
  - `MM/DD/YYYY`, for example `04/25/2024`.
  - `DD/MM/YYYY`, for example `25/04/2024`.
  - `YYYY-MM-DD`, for example `2024-04-25`.

After the schema is inferred, Frictionless validates every row against it.
Values that do not match the inferred type, format, or required constraint are
reported as validation errors.

## Errors currently presented in the report

### Missing header

**Error type:** `missing-label`

A column in the header row has no name. Every column should have a unique,
non-empty header.

### Duplicate header

**Error type:** `duplicate-label`

Two or more columns share the same name. Column names must be unique.

### Empty row

**Error type:** `blank-row`

This row has no data. Rows should contain at least one cell with data.

### Type mismatch

**Error type:** `type-error`

A cell value does not match the expected data type or format for the column.

For example, when most values in a column are numeric, a text value is
reported as invalid:

```csv
amount
100
250.50
300
invalid
```

The same rule applies to dates. Once a date format is detected, values that do
not match that format are reported as invalid:

```csv
date
2024-04-25
2024-05-10
25/06/2024
```

### Missing value

**Error type:** `missing-cell`

This cell is missing data.

### Extra cell

**Error type:** `extra-cell`

This row has more values than the header row.

```csv
column_1,column_2
1,2
3,4,5
```

### Missing header

**Error type:** `blank-header`

A column in the header row has no name. Every column should have a unique,
non-empty header.

### Blank label

**Error type:** `blank-label`

A label in the header row is missing a value. Labels must not be blank.

```csv
column_1,
1,2
3,4
```

### Structural validation error

**Error type:** `structure-error`

The validator could not extract row-level errors from the validation report.

This is a fallback error generated by `ckanext-validate` when the validation
fails but Frictionless does not provide detailed row-level errors.

## Error report behavior

Validation errors are grouped by error type.

For each group, the report displays:

- A user-friendly title.
- A description of the error.
- The total number of occurrences.
- A preview of the affected rows and cells.
- Up to 20 affected rows.

When a group contains more than 20 rows, only the first 20 are displayed.
